# ADR a878ypj5: 테스트 범위 (꼭 필요한 테스트만 둡니다)

## 맥락

2026-10-13 기준 bats 테스트는 237개였습니다. [test-pruning 계획](../plans/plan-2026-10-13-g57mry4b-test-pruning.md)에서 서브에이전트 4개가 모든 테스트를 같은 기준으로 분류했고, 상당수가 다음 중 하나였습니다.

- **실패 문구만 확인하는 테스트.** `set -euo pipefail` 때문에 문구가 없어도 스크립트는 똑같이 실패합니다.
- **같은 동작을 두 번 확인하는 테스트.** 예: `common.bats`의 헬퍼 단위 테스트와, 같은 헬퍼를 거치는 스크립트 전체 경로 테스트
- **입력값만 바꾼 변형 테스트.** 예: nc 응답 메시지 3종, 잘못된 IP 여러 개
- **usage 문구 확인과, 이미 끝난 OCI→GCP 전환의 잔재 검사**

테스트가 많으면 문구 하나를 바꿀 때 고칠 곳이 늘고 `make check`도 길어집니다.

## 결정

1. 다음 중 하나라도 지키는 테스트만 둡니다.
   - AGENTS.md 불변식: 127.0.0.1 바인딩, Funnel 금지, 공개 인그레스 0, digest 고정, 비밀값 비출력, macOS bash 3.2, 스크립트 머리 규칙
   - 데이터 안전: 백업 삭제·덮어쓰기 금지, `.prev-*` 보존, restore 확인, 롤백, 노트 유실 방지
   - 각 스크립트·Make 진입점의 대표 성공 경로 1개
   - 조용히 넘어가거나 파괴적으로 끝날 실패 경로, 실제로 일어난 회귀
   - 머지 절차가 기대는 Git·리뷰 정책
2. 다음은 새로 쓰지 않습니다.
   - 다른 테스트와 같은 동작을 검사하는 중복 테스트
   - 문구·형식만 확인하는 테스트
   - 스텁이나 헬퍼 자체를 검사하는 테스트
   - 상수나 문서 문구를 되풀이하는 변경 감지 테스트
   - usage 문구 확인
3. 입력값만 다른 경우는 대표 테스트 하나의 반복문으로 씁니다. 테스트 이름은 반복문이 무엇을 모두 검사하는지 드러냅니다.
4. 문서 문구를 되풀이하던 검사는 지웁니다: AGENTS.md 줄 수, 런북 섹션 이름, OCI 잔재, AGENTS.md 안전 문구. 상대 링크 검사와 문서 경로 검사는 둡니다. [skill-structure ADR](adr-2026-10-13-m0xvj6rr-skill-structure.md) 결정 7이 `tests/skills.bats`에 맡긴 스킬 규칙 검사도 모두 둡니다. [test-pruning 계획](../plans/plan-2026-10-13-g57mry4b-test-pruning.md)에서 두 가지 모두 추천안으로 정했습니다.

## 결과

**Verified (2026-10-13):**

**Command:** `make check` (계획 브랜치 `plan/g57mry4b-test-pruning`, 686ea6a)

- 테스트 237개 → 148개(삭제 63개, 병합 26개). 148개 모두 PASS했고 실패는 0개입니다.
- 라인 커버리지 97.97% → 96.96%(최소 80%). `scripts/` 아래 모든 실행 스크립트가 여전히 테스트에서 실행됩니다.
- 테스트가 닿지 않게 된 측정 줄은 7개입니다. 모두 usage, 안내 문구, 멱등 건너뛰기 분기라서, 실패는 테스트가 없어도 그대로 드러납니다.
  - `scripts/restore.sh:89`: 이전 데이터가 없는 VM에서 교체 전에 실패했을 때의 안내 문구
  - `scripts/verify-mcp.sh:41`: 알 수 없는 옵션의 usage
  - `scripts/verify-vm.sh:97`: usage
  - `scripts/bootstrap-vm.sh:49-50`: 업로드 실패 시 원격 임시 파일 정리와 안내
  - `scripts/remote/bootstrap.sh:100-101`: 관리자 계정이 이미 docker 그룹일 때 건너뛰기
- kcov가 세는 위 줄 외에도, 한 줄로 쓴 `cmd || die "..."` 분기 중 일부는 유일한 테스트를 잃었습니다. kcov는 이 분기를 따로 세지 않고, 이 분기도 `set -euo pipefail` 아래에서 여전히 실패합니다.
- 모든 스크립트와 스텁이 실행 가능한지 보는 테스트를 지웠습니다. `tools/coverage.sh`는 스크립트를 `-perm -u+x`로 찾으므로, 실행 권한이 없는 새 스크립트는 테스트가 없어도 커버리지 존재 검사를 통과합니다. 다만 Makefile이 스크립트를 직접 호출하므로 첫 Make 실행에서 실패합니다.

## 대체 범위

- 대체된 OCI 스펙(`docs/specs/spec-2026-10-07-p7h3jvpf-basic-memory-oci-tailscale.md`) §9의 다음 요구는 이 ADR로 대체합니다.
  - "스크립트마다 필수 명령·env 누락과 원격 단계 실패를 검증": 이제는 대표 사례만 검증합니다.
  - "`AGENTS.md`는 100줄 이하": 더 이상 테스트하지 않습니다.
  - "모든 Make 타깃이 `help`에 나옴": 모든 타깃에 `##` 설명이 있고 `.PHONY`에 선언됐는지만 검사합니다.
  - "실패 메시지에는 고치는 방법을 포함": 문구 테스트를 지웠으므로 리뷰에서 확인합니다.
- GCP 스펙 §9가 요구하는 테스트(스왑, `status`의 스왑 경고, 클라우드 중립)는 그대로 남아 있습니다.
